## Delivery order

1. **Establish the baseline and protect ongoing work.** Inventory the 18 cases against the current revision. Reproduce the relevant passing tests, record gaps, and map cases to existing issues, requirements and architecture decisions before allocating new ones.
2. **Complete the record and operational slices.** Land the Phase 4 Stores location workflow in coordination with its existing handoff, then complete maintenance history, damage and repair records, technical-log provenance and intraday planning in dependency order. 3. **Build one signing workflow end to end.** Begin with one defined work-card action using synthetic data. Resolve the signature policy, then deliver preview and intent, version binding, qualification and inspection checks, signature evidence, archive confirmation and offline verification. Extend the pattern to other actions only after testing its application to each. 4. **Verify independent exchange.** Use the same synthetic case for an issuer and an independent recipient. Expand to standards-based transfer and sandbox signing provider evidence. Make it possible to rebuild and verify the receiving state with clearly identified differences. Compatibility with existing operator systems is an adoption requirement.
5. **Exercise rollout and retain evidence.** Rehearse installation or migration, user training, parallel operation, reconciliation, rollback and stabilisation in an isolated environment. Keep test data synthetic. Use existing project procedures for any external pilot, certification claim, live cutover or production data access.

Use small reviewable increments and continue through all 18 cases. Reuse records, permissions, history and calculation services. Cover normal entry points, older data, authorisation boundaries, absence of required evidence, partial failures, retries and concurrent updates where applicable. ## Required integrated trial

Create a single synthetic aircraft with these three linked pieces of evidence.

- **One unresolved deferred defect.** Retain the original report, recording actor, deferral decision and basis, due limit and relevant restriction. Confirm the receiver can identify the open item and reach the same conclusion about its status.
- **One recurring inspection.** Retain approved or applicable source reference, issued revision, interval, last completion and supporting measurements. Have the receiving side calculate the next due independently and compare it with the sender’s result.
- **One corrected signed record.** Retain the originally signed version, signed correction or superseding evidence and their relationship, reason, actor, authority and time. Verify both versions and their relationship using independently acquired trust information. Preserve the existing unsigned utilisation-correction baseline as a separate regression.

Exercise the following path through normal tools and screens where available.

1. Create the records using the relevant sample roles. Record the stop conditions and the system of record for the exercise.
2. Sign and archive the original, record a correction and produce the transfer package. Verify that pending work and the correction history remain visible.
3. Transfer the package to the independent receiver, verify it offline, import into an independent instance or second implementation and reconcile the three records. Repeat the import without duplicate records or side effects.
4. Run negative cases with altered evidence, a missing dependency, wrong aircraft, expired or absent authorisation and a failure between signing and archiving. Check refusal, recoverable states and preservation of existing evidence.
5. Compare the records before and after an export, import and reload. Record time to reconcile, entries rekeyed, missing or changed records, and items the receiver could not verify. An unexplained loss or change to any seeded item fails the trial.
6. Rehearse fallback using the established record and compare the restored system with the recorded baseline.
